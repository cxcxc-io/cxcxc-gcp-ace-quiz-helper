# 1. 到府按摩開張：部署到 Cloud Run

> 對應講義：Cloud Run：部署、改版與自動調度 → Lab 實作 →「到府按摩開張：部署到 Cloud Run」
>
> 先完成 GKE 章的 [5-收攤](../GKE微服務架構/5-收攤.md)。這一章直接部署 DevSecOps 章打包的 `quiz-helper:v1.1`，**不用切換程式碼**（`lab-3` 和 `lab-2` 的程式碼相同）。

## 步驟 1：設定這一章會用到的變數

講義沒有對應的 Console 動作。

```bash
gcloud config set project <你的專案 ID>
export PROJECT_ID=$(gcloud config get-value project)
export REGION=asia-east1
export SA_EMAIL=quiz-helper@${PROJECT_ID}.iam.gserviceaccount.com
export IMAGE_V11=${REGION}-docker.pkg.dev/${PROJECT_ID}/quiz-helper/quiz-helper:v1.1
echo "${PROJECT_ID} ${SA_EMAIL} ${IMAGE_V11}"
```

**你應該會看到**：印出專案 ID、服務帳戶 email 與 v1.1 映像檔名稱。

## 步驟 2：啟用 Cloud Run API

對應講義：在程式庫搜尋 Cloud Run Admin API，按「啟用」。

```bash
gcloud services enable run.googleapis.com
```

**你應該會看到**：`Operation "operations/..." finished successfully.`，或沒有輸出（代表之前已啟用）。

## 步驟 3：部署 v1.1

對應講義：Cloud Run →「部署容器」，映像檔選 v1.1、服務名稱 quiz-helper、區域 asia-east1、允許公開存取、安全性分頁的服務帳戶選 quiz-helper。

```bash
gcloud run deploy quiz-helper \
  --image=${IMAGE_V11} \
  --region=${REGION} \
  --service-account=${SA_EMAIL} \
  --no-invoker-iam-check
```

- `--image`：跟 GKE 用的是同一個映像檔，程式一行都不用改
- `--service-account`：服務身分。小幫手用服務帳戶 `quiz-helper` 的身分讀寫 Firestore、值區，就是 IAM 進階章收斂過的那組權限
- `--no-invoker-iam-check`：不檢查呼叫者的叫用者角色，任何人不用登入就能開（公開網站）。另一種做法 `--allow-unauthenticated` 是把叫用者角色授予 `allUsers`，組織有「網域限制共用」政策時會被擋下（講義第 4 節）

**你應該會看到**：最後印出 `Service [quiz-helper] revision [quiz-helper-00001-xxx] has been deployed and is serving 100 percent of traffic.` 與 `Service URL: https://quiz-helper-....asia-east1.run.app`。

## 步驟 4：確認小幫手在 Cloud Run 上回應

對應講義：服務詳細資料頁面上方的網址，用手機打開。

```bash
export RUN_URL=$(gcloud run services describe quiz-helper --region=${REGION} --format="value(status.url)")
echo "小幫手網址：${RUN_URL}"
curl -s ${RUN_URL}/api/question | grep -o '"version".*'
```

- `--format="value(status.url)"`：取出服務的網址
- `/api/question`：隨機取一題，回應裡有版本、平台與執行個體名稱

**你應該會看到**：`"version":"v1.1","platform":"Cloud Run","instance":"quiz-helper-00001-xxx / ..."`。用手機打開 `RUN_URL`（這次是 `https://`）答幾題，題目下方顯示「這一題由 Cloud Run「quiz-helper-00001-… / …」回應」。

### 為什麼不用 /healthz？

Cloud Run 保留了一些路徑，以 `z` 結尾的路徑（例如 `/healthz`）可能被 Google 前端直接攔下、回 404，請求不會送到容器。部署到 Cloud Run 的服務，路徑最好避開 `z` 結尾。

```bash
curl -s -o /dev/null -w "%{http_code}\n" ${RUN_URL}/healthz
```

**你應該會看到**：通常是 `404`，請求沒有到達小幫手。如果剛好回 `200`，也不代表可以放心使用這類路徑，Google 不保證會轉給容器。
