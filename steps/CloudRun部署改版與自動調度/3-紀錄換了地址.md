# 3. 紀錄換了地址

> 對應講義：Cloud Run：部署、改版與自動調度 → Lab 實作 →「紀錄換了地址」
>
> 先完成 [1-到府按摩開張](1-到府按摩開張.md)，並用手機故意答錯 3～5 題。

## 步驟 1：在 Cloud Run 的紀錄裡找答錯的題目

對應講義：記錄檔探索工具貼上四行查詢條件，時間範圍選過去 1 小時。

```bash
gcloud logging read \
  'resource.type="cloud_run_revision" AND resource.labels.service_name="quiz-helper" AND jsonPayload.event="answer" AND jsonPayload.correct=false' \
  --freshness=1h \
  --limit=5 \
  --format="table(timestamp, jsonPayload.nickname, jsonPayload.question_id, resource.labels.revision_name)"
```

- `resource.type="cloud_run_revision"`：紀錄來自 Cloud Run；VM 是 `gce_instance`，GKE 是 `k8s_container`
- `resource.labels.revision_name`：是哪一個修訂版處理的

**你應該會看到**：剛才答錯的幾題，修訂版是 `quiz-helper-00001-xxx`。

## 步驟 2：Cloud Logging 章的指標算不到 Cloud Run

對應講義：Logging →「紀錄型指標」，看 quiz_helper_wrong_answers 的篩選器。

```bash
gcloud logging metrics describe quiz_helper_wrong_answers --format="value(filter)"
```

**你應該會看到**：`resource.type="gce_instance" AND ...`。這個指標只數 VM 上的答錯紀錄，小幫手搬到 Cloud Run 之後就不會再增加了。

## 步驟 3：修改篩選器，讓它也算 Cloud Run

對應講義：在指標那一列按「⋮」→「編輯指標」，把篩選器的第一行改成同時包含 gce_instance 與 cloud_run_revision，按「更新指標」。

```bash
gcloud logging metrics update quiz_helper_wrong_answers \
  --log-filter='resource.type=("gce_instance" OR "cloud_run_revision") AND jsonPayload.event="answer" AND jsonPayload.correct=false'
```

- `resource.type=("gce_instance" OR "cloud_run_revision")`：兩種來源都算
- 名稱不變，Cloud Monitoring 裡的指標還是 `logging.googleapis.com/user/quiz_helper_wrong_answers`，之前的資料點也保留

**你應該會看到**：`Updated [quiz_helper_wrong_answers].`

## 步驟 4：在 Metrics Explorer 看 Cloud Run 的資料點

對應講義：Metrics Explorer 搜尋 quiz_helper_wrong_answers，選「Cloud Run 修訂版本」底下的那一個。

指標只計算修改之後的紀錄。用手機再故意答錯幾題，等 2～3 分鐘，到 Console：「Monitoring」→「Metrics Explorer」→ 選取指標，搜尋 `quiz_helper_wrong_answers`，這次會出現在「Cloud Run 修訂版本」（Cloud Run Revision）底下 → 套用。

**你應該會看到**：折線圖出現資料點，數值就是修改之後答錯的次數。同一個指標在「VM 執行個體」底下還留著 Cloud Logging 章的舊資料。
