# 2. 沒人叫單就收工：看執行個體縮到零

> 對應講義：Cloud Run：部署、改版與自動調度 → Lab 實作 →「沒人叫單就收工：看執行個體縮到零」
>
> 先完成 [1-到府按摩開張](1-到府按摩開張.md)。

## 步驟 1：連續叫單，看執行個體名稱

對應講義：用手機連續答幾題，看題目下方的執行個體。

```bash
for i in $(seq 1 20); do curl -s ${RUN_URL}/api/question | grep -o '"instance":"[^"]*"'; done | sort | uniq -c
```

- `seq 1 20`：連續問 20 題
- `sort | uniq -c`：統計每一個執行個體回應了幾次

**你應該會看到**：通常只有一個執行個體回應全部 20 次。一個執行個體預設可以同時處理 80 個請求（並行數，講義第 6 節），這點流量一位師傅就接得完。

## 步驟 2：看服務的調度設定

對應講義：服務詳細資料 →「修訂版本」→ 點最新的修訂版，看「調度」的最少與最多執行個體數。

```bash
gcloud run services describe quiz-helper --region=${REGION} \
  --format="yaml(spec.template.metadata.annotations, spec.template.spec.containerConcurrency)"
```

- `autoscaling.knative.dev/maxScale`：最多執行個體數；沒有這一行代表用預設上限
- `autoscaling.knative.dev/minScale`：最少執行個體數；沒有這一行代表 0，沒人叫單時可以縮到零
- `containerConcurrency`：並行數

**你應該會看到**：`containerConcurrency: 80`，而且沒有 `minScale`。

## 步驟 3：等它縮到零

對應講義：服務詳細資料 →「指標」分頁 →「容器執行個體數量」。

這一步只能在 Console 看圖：停止答題，閒置約 15 分鐘後，「容器執行個體數量」的「作用中」降到 0。之後再打開小幫手，第一題會稍微慢一點（冷啟動），接著恢復正常。

> 比較 GKE：Deployment 會一直保留你指定的 Pod 數，沒人用也照樣計費；Cloud Run 沒有請求時不計費（預設的「依請求計費」，講義第 6 節）。
