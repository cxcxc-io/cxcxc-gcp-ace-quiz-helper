# 2. 查出是誰改了防火牆

> 對應講義：Cloud Logging → Lab 實作 →「查出是誰改了防火牆」

## 開始前：確認 Cloud Shell 在你的專案

講義沒有對應的 Console 動作。Cloud Shell 不一定停在這門課的專案（重開 Cloud Shell、從別的專案頁面打開、或之前切換過專案都可能），所以每一份都先執行這一段，順便把這一份要用的變數設好。

```bash
gcloud config set project "你的專案ID"
export PROJECT_ID=$(gcloud config get-value project)
echo "目前專案：${PROJECT_ID}"
```

- `"你的專案ID"`：換成你的專案 ID（Console 上方的專案選單看得到），雙引號保留

**你應該會看到**：`Updated property [core/project].`，接著印出你的專案 ID。出現 `WARNING: You do not appear to have access to project` 代表專案 ID 打錯了。

## 步驟 1：找出防火牆規則的異動

對應講義：查管理活動稽核紀錄、方法名稱包含 firewalls。

```bash
gcloud logging read \
  'logName:"cloudaudit.googleapis.com%2Factivity" AND protoPayload.methodName:"firewalls"' \
  --freshness=7d \
  --format="table(timestamp, protoPayload.methodName, protoPayload.resourceName.basename(), protoPayload.authenticationInfo.principalEmail)"
```

- `logName:"cloudaudit.googleapis.com%2Factivity"`：管理活動稽核紀錄（講義第 5 節表 3）
- `protoPayload.methodName:"firewalls"`：冒號代表「包含」，方法名稱裡有 firewalls 的都算
- `protoPayload.resourceName.basename()`：只取資源路徑的最後一段，也就是規則名稱
- `protoPayload.authenticationInfo.principalEmail`：是誰做的
- `--freshness=7d`：查過去 7 天。做 VPC 章已經超過 7 天的話，把數字改大

**你應該會看到**：`firewalls.insert`（建立 allow-quiz-helper-http、allow-iap-ssh）與 `firewalls.patch`（停用 default-allow-ssh），最後一欄都是你的帳號。

## 步驟 2：找出網路標記的異動

對應講義：把方法名稱改成 setTags。

```bash
gcloud logging read \
  'logName:"cloudaudit.googleapis.com%2Factivity" AND protoPayload.methodName:"setTags"' \
  --freshness=7d \
  --format="table(timestamp, protoPayload.methodName, protoPayload.resourceName.basename(), protoPayload.authenticationInfo.principalEmail)"
```

**你應該會看到**：`quiz-helper-vm` 的幾筆 `setTags`，包含 Cloud Monitoring 章演練時拿掉、加回網路標記的兩筆，時間就是那次演練。
