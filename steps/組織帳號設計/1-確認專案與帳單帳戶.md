# 1. 確認專案與帳單帳戶

> 對應講義：組織帳號設計 → Lab 實作 →「確認專案與帳單帳戶」

## 這一段做什麼

確認接下來的資源都建在上課用的專案裡，而且這個專案已經綁了帳單帳戶。講義這一段是在 Console 操作；指令版要在 Cloud Shell 裡執行，還沒開過 Cloud Shell 的話，先做 [2-打開CloudShell並取得程式碼](2-打開CloudShell並取得程式碼.md)，再回來執行。

## 指令

```bash
# 列出你能存取的專案，找到上課用的那一個
gcloud projects list

# 把 gcloud 的預設專案設成上課用的專案（只有這一行要自己換成專案 ID）
gcloud config set project <你的專案 ID>

# 把專案 ID 與區域存成變數，後面的指令都會用到
export PROJECT_ID=$(gcloud config get-value project)
export REGION=asia-east1
echo "專案：${PROJECT_ID}，區域：${REGION}"

# 查這個專案綁的帳單帳戶
gcloud billing projects describe ${PROJECT_ID}
```

## 每個指令在做什麼

| 指令或參數 | 說明 |
| --- | --- |
| `gcloud projects list` | 列出你有權限看到的專案，欄位有 `PROJECT_ID`、`NAME`、`PROJECT_NUMBER`。後面要用的是 `PROJECT_ID`，不是 `NAME` |
| `gcloud config set project` | 設定 gcloud 的預設專案。之後的指令沒有加 `--project` 時，都會作用在這個專案 |
| `gcloud config get-value project` | 讀出目前的預設專案 ID，存進變數 `PROJECT_ID`，避免每次手打 |
| `REGION=asia-east1` | 台灣區域。本課程的資源都放在這裡 |
| `gcloud billing projects describe` | 顯示專案的帳單資訊 |

## 預期看到的結果

最後一個指令印出類似：

```
billingAccountName: billingAccounts/XXXXXX-XXXXXX-XXXXXX
billingEnabled: true
name: projects/<你的專案 ID>/billingInfo
projectId: <你的專案 ID>
```

- `billingEnabled: true`：已綁帳單帳戶，可以繼續
- `billingEnabled: false`：還沒綁，回講義照 Console 步驟連結帳單帳戶

> Cloud Shell 閒置一段時間會斷線，重新連上後 `PROJECT_ID`、`REGION` 變數會消失，再執行一次 `export` 那兩行即可。
