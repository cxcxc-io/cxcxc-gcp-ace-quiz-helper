# 1. 打開小幫手的內建偵測器

> 對應講義：Cloud Monitoring → Lab 實作 →「打開小幫手的內建偵測器」
>
> 先完成 [ComputeEngine虛擬機器/0-開始前](../ComputeEngine虛擬機器/0-開始前.md)，設定 `PROJECT_ID`、`ZONE`、`SA_EMAIL` 等變數。

## 步驟 1：在 VM 的中繼資料打開 Node Problem Detector

對應講義：quiz-helper-vm「編輯」→「中繼資料」加上 google-monitoring-enabled = true。

```bash
gcloud compute instances add-metadata quiz-helper-vm --zone=${ZONE} \
  --metadata=google-monitoring-enabled=true
```

- `google-monitoring-enabled=true`：Container-Optimized OS 讀到這個中繼資料，就會啟動內建的 Node Problem Detector（講義第 4 節表 3）

## 步驟 2：讓小幫手的服務帳戶能送出指標

對應講義：在 quiz-helper 那一列加入「Monitoring 指標寫入者」。

```bash
gcloud projects add-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/monitoring.metricWriter" \
  --condition=None --format=none
```

- `roles/monitoring.metricWriter`：只能寫入指標，不能讀取或修改監控設定。偵測器用的是 VM 附加的服務帳戶，也就是 quiz-helper

## 步驟 3：確認偵測器有在執行

講義沒有對應的 Console 動作：連進 VM 看服務狀態。

```bash
gcloud compute ssh quiz-helper-vm --zone=${ZONE} --tunnel-through-iap \
  --command="sudo systemctl is-active node-problem-detector"
```

- VPC 章已經改成只能走 IAP、用 OS Login 登入，所以要加 `--tunnel-through-iap`
- `systemctl is-active`：只印出服務狀態

**你應該會看到**：`active`

> 印出 `inactive`：重新開機一次，讓它在開機時讀到中繼資料：
>
> ```bash
> gcloud compute instances reset quiz-helper-vm --zone=${ZONE}
> ```
>
> 重開期間小幫手會中斷一兩分鐘。

## 步驟 4：在 Metrics Explorer 看指標

這一步用 Console 看最清楚：「Monitoring → Metrics Explorer」，資源類型選「VM 執行個體」，指標搜尋 `guest`，篩選 `quiz-helper-vm`。指標要幾分鐘後才會出現。
