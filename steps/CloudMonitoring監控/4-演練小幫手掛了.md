# 4. 演練：小幫手掛了

> 對應講義：Cloud Monitoring → Lab 實作 →「演練：小幫手掛了」
>
> 這個小 Lab 的重點在 Console：看事件、Cloud Hub、Personalized Service Health 與 Gemini Cloud Assist。指令只用來製造與排除故障。

## 開始前：確認 Cloud Shell 在你的專案

講義沒有對應的 Console 動作。Cloud Shell 不一定停在這門課的專案（重開 Cloud Shell、從別的專案頁面打開、或之前切換過專案都可能），所以每一份都先執行這一段，順便把這一份要用的變數設好。

```bash
gcloud config set project "你的專案ID"
export PROJECT_ID=$(gcloud config get-value project)
export ZONE=asia-east1-b
export VM_IP=$(gcloud compute instances describe quiz-helper-vm --zone=${ZONE} \
  --format="value(networkInterfaces[0].accessConfigs[0].natIP)")
echo "目前專案：${PROJECT_ID}"
```

- `"你的專案ID"`：換成你的專案 ID（Console 上方的專案選單看得到），雙引號保留

**你應該會看到**：`Updated property [core/project].`，接著印出你的專案 ID。出現 `WARNING: You do not appear to have access to project` 代表專案 ID 打錯了。

## 步驟 1：拿掉網路標記，讓外面連不進來

對應講義：「網路標記」刪掉 quiz-helper。

```bash
gcloud compute instances remove-tags quiz-helper-vm --zone=${ZONE} --tags=quiz-helper
```

- 拿掉之後，VPC 章建立的 `allow-quiz-helper-http` 就不再套用到這台 VM，運作時間檢查也連不進來

## 步驟 2：確認運作時間檢查失敗

```bash
gcloud monitoring uptime list-configs --filter='displayName="quiz-helper-healthz"' \
  --format="value(displayName, httpCheck.path)"
curl -s --max-time 5 http://${VM_IP}/healthz; echo "結束代碼：$?"
```

**你應該會看到**：`curl` 逾時（結束代碼 `28`）。幾分鐘後信箱收到警示信，Console 的「Monitoring → 警示」出現一筆開啟中的事件。接著照講義到 Cloud Hub、Personalized Service Health、Gemini Cloud Assist 走一遍。

## 步驟 3：把網路標記加回去

對應講義：把 quiz-helper 網路標記加回 VM。

```bash
gcloud compute instances add-tags quiz-helper-vm --zone=${ZONE} --tags=quiz-helper
curl -s --max-time 5 http://${VM_IP}/healthz; echo
```

**你應該會看到**：`{"status":"ok","version":"v1"}`。幾分鐘後事件自動關閉，信箱收到恢復通知。
