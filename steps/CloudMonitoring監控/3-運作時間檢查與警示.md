# 3. 運作時間檢查與警示

> 對應講義：Cloud Monitoring → Lab 實作 →「運作時間檢查與警示」
>
> 用 Console 做比較直覺：建立運作時間檢查時，可以一併建立警示政策和通知管道。指令版要分三步：通知管道、運作時間檢查、警示政策。

## 步驟 1：取得小幫手的外部 IP

```bash
export VM_IP=$(gcloud compute instances describe quiz-helper-vm --zone=${ZONE} \
  --format="value(networkInterfaces[0].accessConfigs[0].natIP)")
echo ${VM_IP}
```

## 步驟 2：建立 email 通知管道

對應講義：「管理通知管道」→「電子郵件」→「新增」。

```bash
export MY_EMAIL=<你的 email>
gcloud beta monitoring channels create \
  --display-name="我的信箱" \
  --type=email \
  --channel-labels=email_address=${MY_EMAIL}
export CHANNEL=$(gcloud beta monitoring channels list \
  --filter="displayName=我的信箱" --format="value(name)" | head -1)
echo ${CHANNEL}
```

- 通知管道的指令目前在 `gcloud beta` 底下
- `CHANNEL`：通知管道的完整名稱，格式是 `projects/<專案 ID>/notificationChannels/<編號>`，下面建立警示政策時要用

## 步驟 3：建立運作時間檢查

對應講義：通訊協定 HTTP、主機名稱填外部 IP、路徑 /healthz、內容比對包含 ok、標題 quiz-helper-healthz。

```bash
gcloud monitoring uptime create quiz-helper-healthz \
  --resource-type=uptime-url \
  --resource-labels=host=${VM_IP},project_id=${PROJECT_ID} \
  --protocol=http \
  --path=/healthz \
  --period=1 \
  --matcher-content=ok \
  --matcher-type=contains-string
```

- `--resource-type=uptime-url`：檢查的對象是一個網址
- `--period=1`：每 1 分鐘檢查一次
- `--matcher-content=ok`、`--matcher-type=contains-string`：回應內容要包含 `ok` 才算正常

## 步驟 4：取得運作時間檢查的編號

```bash
export CHECK_ID=$(gcloud monitoring uptime list-configs \
  --filter="displayName=quiz-helper-healthz" --format="value(name)" | sed 's|.*/||')
echo ${CHECK_ID}
```

- `sed 's|.*/||'`：只留下最後一段編號

## 步驟 5：建立警示政策

對應講義：建立運作時間檢查時「保持勾選建立警示」。

```bash
cat > /tmp/uptime-policy.json <<JSON
{
  "displayName": "小幫手連不上",
  "combiner": "OR",
  "conditions": [{
    "displayName": "quiz-helper-healthz 失敗",
    "conditionThreshold": {
      "filter": "metric.type=\"monitoring.googleapis.com/uptime_check/check_passed\" AND resource.type=\"uptime_url\" AND metric.label.\"check_id\"=\"${CHECK_ID}\"",
      "aggregations": [{
        "alignmentPeriod": "60s",
        "perSeriesAligner": "ALIGN_NEXT_OLDER",
        "crossSeriesReducer": "REDUCE_COUNT_FALSE",
        "groupByFields": ["resource.label.host"]
      }],
      "comparison": "COMPARISON_GT",
      "thresholdValue": 1,
      "duration": "60s",
      "trigger": {"count": 1}
    }
  }],
  "notificationChannels": ["${CHANNEL}"]
}
JSON
gcloud monitoring policies create --policy-from-file=/tmp/uptime-policy.json
```

- `check_passed`：每個檢查地區每次檢查的結果，成功是 true、失敗是 false
- `REDUCE_COUNT_FALSE`：數一數有幾個地區失敗
- `COMPARISON_GT` 與 `thresholdValue: 1`：超過 1 個地區失敗才觸發，避免單一地區的網路抖動造成誤報
- `duration: 60s`：狀況持續 60 秒才發出警示

**你應該會看到**：印出新建立的警示政策，`displayName: 小幫手連不上`。
