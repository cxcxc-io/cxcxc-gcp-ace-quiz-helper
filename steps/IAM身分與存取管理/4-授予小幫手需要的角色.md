# 4. 授予小幫手需要的角色

> 對應講義：IAM 身分與存取管理 → Lab 實作 →「授予小幫手需要的角色」
>
> 這一份用到上一份的變數 `SA_EMAIL`。Cloud Shell 斷線過的話，先重新執行 [3-建立小幫手的服務帳戶](3-建立小幫手的服務帳戶.md) 的步驟 2。

講義裡你在「授予存取權」一次加了四個角色。指令一次只能授予一個角色，所以這裡分四次。

## 步驟 1：讀寫題庫（Firestore）

對應講義：加入「Cloud Datastore 使用者」。

```bash
gcloud projects add-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/datastore.user" \
  --condition=None --format=none
```

- `--member="serviceAccount:..."`：主體是服務帳戶，前綴是 `serviceAccount:`，不是 `user:`
- `roles/datastore.user`：Firestore 沿用 Datastore 的角色名稱，所以讀寫 Firestore 用的是這個
- `--format=none`：不印出整份允許政策，畫面比較乾淨

**你應該會看到**：`Updated IAM policy for project [...]`

> 出現 `Service account ... does not exist`：服務帳戶剛建立，還沒在整個系統生效，等一分鐘再執行一次。

## 步驟 2：寫紀錄（Cloud Logging）

對應講義：加入「記錄寫入者」。

```bash
gcloud projects add-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/logging.logWriter" \
  --condition=None --format=none
```

- `roles/logging.logWriter`：只能寫入紀錄，不能讀

## 步驟 3：讀取題庫檔案（Cloud Storage）

對應講義：加入「Storage 管理員」。

```bash
gcloud projects add-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/storage.admin" \
  --condition=None --format=none
```

- `roles/storage.admin`：可以管理專案裡所有值區與物件，**包括刪除**。這一章先給寬，「IAM 進階」章會收斂

## 步驟 4：拉取映像檔（Artifact Registry）

對應講義：加入「Artifact Registry 讀取者」。

```bash
gcloud projects add-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/artifactregistry.reader" \
  --condition=None --format=none
```

- `roles/artifactregistry.reader`：授予在專案上，代表能讀專案裡**所有**存放區。存放區要到 Compute Engine 章才建立，現在先給在專案上

## 步驟 5：確認四個角色都在

對應講義：quiz-helper 那一列有四個角色。

```bash
gcloud projects get-iam-policy ${PROJECT_ID} \
  --flatten="bindings[].members" \
  --filter="bindings.members:serviceAccount:${SA_EMAIL}" \
  --format="value(bindings.role)"
```

- 跟上一份確認講師權限的指令一樣，只是主體換成服務帳戶

**你應該會看到**：四行（順序可能不同）

```
roles/artifactregistry.reader
roles/datastore.user
roles/logging.logWriter
roles/storage.admin
```
