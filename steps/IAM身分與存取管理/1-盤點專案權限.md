# 1. 盤點專案權限

> 對應講義：IAM 身分與存取管理 → Lab 實作 →「盤點：誰在這個專案有什麼權限」
>
> 這一份延續「組織帳號設計」設好的變數 `PROJECT_ID`。Cloud Shell 斷線過的話，先執行 [組織帳號設計/1-確認專案與帳單帳戶](../組織帳號設計/1-確認專案與帳單帳戶.md) 的步驟 2、3。

講義裡你在「IAM 與管理 → IAM」看到每個帳號和它的角色。Console 的這張表，背後就是專案的**允許政策**（回顧講義第 6 節）。這裡用指令把它讀出來。

## 步驟 1：讀出整份允許政策

對應講義：打開「IAM」頁面。

```bash
gcloud projects get-iam-policy ${PROJECT_ID}
```

- `gcloud projects get-iam-policy`：讀出這個專案的允許政策

**你應該會看到**：一段 YAML，裡面有很多 `bindings`，每一筆是一個 `role` 加上一串 `members`。

```
bindings:
- members:
  - user:you@example.com
  role: roles/owner
...
```

- `role`：角色，例如 `roles/owner` 就是「擁有者」
- `members`：拿到這個角色的主體，前綴說明是哪一種：`user:` 是個人帳號、`serviceAccount:` 是服務帳戶、`group:` 是 Google 群組

這就是講義第 4 節說的「角色綁定（role binding）」：一個角色，綁上一群主體。

## 步驟 2：改成「依主體」排的表格

對應講義：「依主體查看」分頁，一個帳號一列。

上一步的輸出是「依角色」排的。加上參數，改成跟 Console 一樣「一個主體一列」：

```bash
gcloud projects get-iam-policy ${PROJECT_ID} \
  --flatten="bindings[].members" \
  --format="table(bindings.members, bindings.role)"
```

- `--flatten="bindings[].members"`：把「一個角色配一串主體」攤平成「一個主體配一個角色」，一列一筆
- `--format="table(...)"`：只顯示主體和角色兩欄

**你應該會看到**：你的帳號對應 `roles/owner`；另外還有幾個 `serviceAccount:` 開頭、帶有 `gcp-sa-` 或 `cloudservices` 的帳號，就是講義說的 Google 服務代理。

> Console 預設會把 Google 服務代理藏起來，要勾選「包含 Google 提供的角色授權」才看得到；指令則是全部列出。
