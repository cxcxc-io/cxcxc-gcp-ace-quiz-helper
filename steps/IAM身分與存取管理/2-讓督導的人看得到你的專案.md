# 2. 讓督導的人看得到你的專案

> 對應講義：IAM 身分與存取管理 → Lab 實作 →「讓督導的人看得到你的專案」

講義裡你在「IAM → 授予存取權」填了講師的 email、選了「基本 → 檢視者」。這在允許政策裡就是新增一筆角色綁定。

## 開始前：確認 Cloud Shell 在你的專案

講義沒有對應的 Console 動作。Cloud Shell 不一定停在這門課的專案（重開 Cloud Shell、從別的專案頁面打開、或之前切換過專案都可能），所以每一份都先執行這一段，順便把這一份要用的變數設好。

```bash
gcloud config set project "你的專案ID"
export PROJECT_ID=$(gcloud config get-value project)
echo "目前專案：${PROJECT_ID}"
```

- `"你的專案ID"`：換成你的專案 ID（Console 上方的專案選單看得到），雙引號保留

**你應該會看到**：`Updated property [core/project].`，接著印出你的專案 ID。出現 `WARNING: You do not appear to have access to project` 代表專案 ID 打錯了。

## 步驟 1：把講師的帳號存成變數

講義沒有對應的 Console 動作：先存成變數，下面的指令就不用改。

```bash
export SUPERVISOR="講師的Google帳號email"
```

- 這是本份唯一要自己改的地方

## 步驟 2：授予檢視者角色

對應講義：「新增主體」填 email、「指派角色」選「檢視者」、按「儲存」。

```bash
gcloud projects add-iam-policy-binding ${PROJECT_ID} \
  --member="user:${SUPERVISOR}" \
  --role="roles/viewer" \
  --condition=None
```

- `gcloud projects add-iam-policy-binding`：在專案的允許政策新增一筆角色綁定
- `--member="user:..."`：主體。個人帳號前面要加 `user:`
- `--role="roles/viewer"`：「基本 → 檢視者」的角色 ID
- `--condition=None`：明確表示這筆授權不加條件。專案裡已經有帶條件的授權時，不加這個參數，gcloud 會停下來問你要不要加條件

**你應該會看到**：`Updated IAM policy for project [...]`，後面印出整份更新後的允許政策。

> 出現與網域或組織政策有關的錯誤：組織開了網域限制共用，不允許組織外的帳號，請找組織管理員（回顧講義「組織帳號設計」章）。

## 步驟 3：確認授權生效

對應講義：清單出現講師的帳號，角色是「檢視者」。

```bash
gcloud projects get-iam-policy ${PROJECT_ID} \
  --flatten="bindings[].members" \
  --filter="bindings.members:user:${SUPERVISOR}" \
  --format="value(bindings.role)"
```

- `--filter="bindings.members:user:..."`：只留下講師這個主體的那幾列
- `--format="value(bindings.role)"`：只印出角色

**你應該會看到**：`roles/viewer`

> 想讓這筆授權到期自動失效？`roles/viewer` 是基本角色，不能加條件（講義第 8 節陷阱）。「IAM 進階」章會改用預先定義角色加上時間條件。
