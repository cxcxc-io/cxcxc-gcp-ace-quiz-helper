# 3. 開發人員卡住了

> 對應講義：IAM 進階 → Lab 實作 →「開發人員卡住了」
>
> 這一份由**開發人員（旁邊的同學）**在**他自己的** Cloud Shell 執行，除了最後一步。

## 開始前：確認 Cloud Shell 在你的專案

講義沒有對應的 Console 動作。Cloud Shell 不一定停在這門課的專案（重開 Cloud Shell、從別的專案頁面打開、或之前切換過專案都可能），所以每一份都先執行這一段，順便把這一份要用的變數設好。

```bash
gcloud config set project "你的專案ID"
export PROJECT_ID=$(gcloud config get-value project)
export SA_EMAIL=quiz-helper@${PROJECT_ID}.iam.gserviceaccount.com
echo "目前專案：${PROJECT_ID}"
```

- `"你的專案ID"`：換成你的專案 ID（Console 上方的專案選單看得到），雙引號保留

**你應該會看到**：`Updated property [core/project].`，接著印出你的專案 ID。出現 `WARNING: You do not appear to have access to project` 代表專案 ID 打錯了。

## 步驟 1：記下對方專案的資訊

講義沒有對應的 Console 動作：開發人員要知道他要存取的是哪個專案。請管理員（你的同學）告訴你他的專案 ID。

```bash
export TARGET_PROJECT="管理員的專案ID"
export TARGET_BUCKET=${TARGET_PROJECT}-gcp-ace-cxcxc
echo ${TARGET_BUCKET}
```

**你應該會看到**：`<管理員的專案 ID>-gcp-ace-cxcxc`

## 步驟 2：試著列出值區裡的檔案

對應講義：開發人員試著列出你專案值區裡的檔案，被拒絕。

```bash
gcloud storage ls gs://${TARGET_BUCKET}/
```

- `gcloud storage ls`：列出值區裡的物件

**你應該會看到**：錯誤訊息，狀態碼 `403`，說明你的帳號沒有 `storage.objects.list` 權限。

## 步驟 3（管理員執行）：看看小幫手有沒有使用者管理的金鑰

對應講義：「服務帳戶 → quiz-helper → 金鑰」分頁，不按「新增金鑰」。

這一步換回**管理員（你）**在自己的 Cloud Shell 執行：

```bash
gcloud iam service-accounts keys list \
  --iam-account=${SA_EMAIL} \
  --managed-by=user
```

- `--managed-by=user`：只列出「使用者自己建立、可以下載」的金鑰。Google 自動管理、會自動輪替的金鑰不會列出

**你應該會看到**：`Listed 0 items.`。小幫手在 VM 上用的是附加的服務帳戶，從頭到尾都不需要金鑰。我們也不打算為了開發人員建立一把。
