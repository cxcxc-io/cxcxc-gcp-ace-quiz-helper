# 4. 讓開發人員模擬小幫手

> 對應講義：IAM 進階 → Lab 實作 →「讓開發人員模擬小幫手」

## 管理員（你）的部分

### 步驟 1：設定開發人員帳號與下課時間

```bash
export DEVELOPER=<開發人員（同學）的 Google 帳號 email>
export CLASS_END=2026-10-26T10:00:00Z
```

- `CLASS_END`：今天下課的時間，用 UTC 寫。台灣時間減 8 小時，例如台灣時間下午 6 點就是 `T10:00:00Z`。日期改成今天

### 步驟 2：在服務帳戶上授予 Token Creator，加上條件

對應講義：「服務帳戶 → quiz-helper → 權限 → 授予存取權」，角色選服務帳戶憑證建立者，加 IAM 條件。

```bash
gcloud iam service-accounts add-iam-policy-binding ${SA_EMAIL} \
  --member="user:${DEVELOPER}" \
  --role="roles/iam.serviceAccountTokenCreator" \
  --condition="expression=request.time < timestamp('${CLASS_END}'),title=今天下課前"
```

- `gcloud iam service-accounts add-iam-policy-binding`：授權給在**服務帳戶**這個資源上，不是專案上（講義 IAM 章「服務帳戶既是身分，也是資源」）
- `roles/iam.serviceAccountTokenCreator`：可以取得這個服務帳戶的短期憑證，也就是模擬它
- `--condition`：上一個小 Lab 學的到期條件

**你應該會看到**：印出服務帳戶的允許政策，裡面有開發人員和條件。

## 開發人員（旁邊的同學）的部分

以下在**開發人員自己的** Cloud Shell 執行，延續上一份的 `TARGET_PROJECT`、`TARGET_BUCKET` 變數。

### 步驟 3：設定要模擬的服務帳戶

```bash
export TARGET_SA=quiz-helper@${TARGET_PROJECT}.iam.gserviceaccount.com
```

### 步驟 4：用模擬身分列出值區

對應講義：加上模擬參數，再列一次值區。

```bash
gcloud storage ls gs://${TARGET_BUCKET}/ \
  --impersonate-service-account=${TARGET_SA}
```

- `--impersonate-service-account`：這一個指令改用指定服務帳戶的身分執行。gcloud 會先用你的帳號換一張這個服務帳戶的短期憑證，再拿它去列出值區

**你應該會看到**：畫面先出現一行警告，說明這個指令正在模擬服務帳戶；接著列出 `gs://.../questions.csv`。上一份同一個指令被拒絕，差別只在借用了小幫手的身分。

> 出現 `403` 或 `Permission 'iam.serviceAccounts.getAccessToken' denied`：管理員剛授予的角色可能還沒生效，等一兩分鐘再試；仍然不行，請管理員確認步驟 2 的帳號與時間。

### 步驟 5：用模擬身分刪除題庫

對應講義：試著刪除 questions.csv，被拒絕。

```bash
gcloud storage rm gs://${TARGET_BUCKET}/questions.csv \
  --impersonate-service-account=${TARGET_SA}
```

**你應該會看到**：`403`，缺少 `storage.objects.delete` 權限。小幫手值區這個自訂角色本來就沒有這個權限，這證明了第 1 個小 Lab 的收斂真的生效。

### 步驟 6：用模擬身分列出 VM

對應講義：試著列出 VM，也被拒絕。

```bash
gcloud compute instances list \
  --project=${TARGET_PROJECT} \
  --impersonate-service-account=${TARGET_SA}
```

- `--project`：開發人員自己的 gcloud 預設專案是他自己的，這裡要指定管理員的專案

**你應該會看到**：`403`，缺少 `compute.instances.list` 權限。
