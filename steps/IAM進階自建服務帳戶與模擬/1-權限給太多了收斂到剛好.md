# 1. 權限給太多了：收斂到剛好

> 對應講義：IAM 進階 → Lab 實作 →「權限給太多了：收斂到剛好」
>
> 先完成 [ComputeEngine虛擬機器/0-開始前](../ComputeEngine虛擬機器/0-開始前.md)：這一份要用 `lab-1` 版本裡的角色定義檔，以及 `PROJECT_ID`、`REGION`、`SA_EMAIL` 變數。

## 步驟 1：看一下自訂角色的定義

講義沒有對應的 Console 動作：Console 是一個個勾選權限，指令版則把同樣的內容寫在檔案裡。

```bash
cat deploy/vm/quiz-helper-bucket-role.yaml
```

**你應該會看到**：`title: 小幫手值區`，`includedPermissions` 列出四個權限：`storage.buckets.get`、`storage.buckets.create`、`storage.objects.list`、`storage.objects.get`。

## 步驟 2：建立自訂角色

對應講義：「IAM 與管理 → 角色 → 建立角色」，填標題、ID、勾選四個權限。

```bash
gcloud iam roles create quizHelperBucket \
  --project=${PROJECT_ID} \
  --file=deploy/vm/quiz-helper-bucket-role.yaml
```

- `quizHelperBucket`：角色 ID，講義填的「ID」
- `--project`：建在專案層級。自訂角色只能建在專案或組織上（講義 IAM 章第 5 節）
- `--file`：從檔案讀出標題、發布階段與權限

**你應該會看到**：`name: projects/<專案 ID>/roles/quizHelperBucket`，`includedPermissions` 列出四個權限。

> 出現「已存在」或「已刪除」：自訂角色刪除後，同一個 ID 會保留一段時間不能重用。已存在就直接做下一步。

## 步驟 3：換掉 Storage 管理員

對應講義：在 quiz-helper 那一列「編輯主體」，刪除 Storage 管理員，加入小幫手值區。

```bash
gcloud projects add-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="projects/${PROJECT_ID}/roles/quizHelperBucket" \
  --condition=None --format=none
gcloud projects remove-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/storage.admin" \
  --condition=None --format=none
```

- 自訂角色的完整名稱是 `projects/<專案 ID>/roles/<角色 ID>`，跟預先定義角色的 `roles/...` 不同
- **先加新的、再移除舊的**：中間不會有小幫手沒權限的空窗

## 步驟 4：把 Artifact Registry 讀取者縮到單一存放區

對應講義：刪除專案層級的 Artifact Registry 讀取者，改到 quiz-helper 存放區的「權限」面板授予。

```bash
gcloud artifacts repositories add-iam-policy-binding quiz-helper \
  --location=${REGION} \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/artifactregistry.reader" \
  --format=none
gcloud projects remove-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/artifactregistry.reader" \
  --condition=None --format=none
```

- `gcloud artifacts repositories add-iam-policy-binding`：授權給在**存放區**這個資源上，不是專案上。這是最小權限的另一種做法：縮小範圍

## 步驟 5：確認結果

對應講義：quiz-helper 在 IAM 頁面只剩三個角色；Artifact Registry 讀取者只出現在存放區上。

```bash
gcloud projects get-iam-policy ${PROJECT_ID} \
  --flatten="bindings[].members" \
  --filter="bindings.members:serviceAccount:${SA_EMAIL}" \
  --format="value(bindings.role)"
gcloud artifacts repositories get-iam-policy quiz-helper --location=${REGION}
```

**你應該會看到**：第一段三行（順序可能不同）：

```
projects/<專案 ID>/roles/quizHelperBucket
roles/datastore.user
roles/logging.logWriter
```

第二段看到 `role: roles/artifactregistry.reader`，`members` 包含 `serviceAccount:quiz-helper@...`。

## 步驟 6：確認小幫手照常運作

對應講義：到管理頁面再匯入一次。

```bash
export VM_IP=$(gcloud compute instances describe quiz-helper-vm --zone=${ZONE} \
  --format="value(networkInterfaces[0].accessConfigs[0].natIP)")
curl -s -X POST http://${VM_IP}/api/import \
  -H "Content-Type: application/json" \
  -d '{"object":"questions.csv"}'
```

- `/api/import`：管理頁面「匯入」按鈕背後呼叫的就是這個網址
- `-d '{"object":"questions.csv"}'`：告訴小幫手要匯入哪個檔案

**你應該會看到**：回傳的結果裡有匯入 5 題。權限是即時生效的，不用重開 VM。
