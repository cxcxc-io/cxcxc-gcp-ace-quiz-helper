# 5. 用簽署網址分享題庫

> 對應講義：IAM 進階 → Lab 實作 →「用簽署網址分享題庫」
>
> 由**開發人員（旁邊的同學）**執行，延續上一份的 `TARGET_BUCKET`、`TARGET_SA` 變數。

## 步驟 1：產生 10 分鐘有效的簽署網址

對應講義：用模擬身分產生 questions.csv 的簽署網址。

```bash
gcloud storage sign-url gs://${TARGET_BUCKET}/questions.csv \
  --impersonate-service-account=${TARGET_SA} \
  --duration=10m
```

- `gcloud storage sign-url`：產生簽署網址。網址裡帶著服務帳戶的簽名與到期時間，拿到網址的人不用登入就能下載
- `--impersonate-service-account`：用 quiz-helper 的身分簽名。Token Creator 角色也包含「代替服務帳戶簽名」的權限
- `--duration=10m`：10 分鐘後失效

**你應該會看到**：一個表格，`signed_url` 欄位是一條很長的 `https://storage.googleapis.com/...` 網址。

## 步驟 2：不帶身分，用簽署網址下載

對應講義：在無痕視窗貼上網址，不用登入就能下載。

```bash
export SIGNED_URL='<貼上剛才的 signed_url>'
curl -s -o /dev/null -w "%{http_code}\n" "${SIGNED_URL}"
```

- 網址裡有 `&` 等特殊符號，所以用**單引號**包起來
- `curl` 沒有帶任何身分，跟 Cloud Storage 章那次匿名存取一樣

**你應該會看到**：`200`。Cloud Storage 章同樣是匿名存取，那次得到 `403`；差別在網址本身帶了簽名。

## 步驟 3：10 分鐘後再試一次

對應講義：過期後同一條網址被拒絕。

```bash
curl -s -o /dev/null -w "%{http_code}\n" "${SIGNED_URL}"
```

**你應該會看到**：`400`，網址已經過期。
