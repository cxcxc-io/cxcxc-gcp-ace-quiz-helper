# 1. 拿掉標記，小幫手打不開了

> 對應講義：VPC 網路 → Lab 實作 →「拿掉標記，小幫手打不開了」
>
> 先完成 [ComputeEngine虛擬機器/0-開始前](../ComputeEngine虛擬機器/0-開始前.md)，設定 `PROJECT_ID`、`ZONE` 等變數。

## 開始前：確認 Cloud Shell 在你的專案

講義沒有對應的 Console 動作。Cloud Shell 不一定停在這門課的專案（重開 Cloud Shell、從別的專案頁面打開、或之前切換過專案都可能），所以每一份都先執行這一段，順便把這一份要用的變數設好。

```bash
gcloud config set project "你的專案ID"
export PROJECT_ID=$(gcloud config get-value project)
export ZONE=asia-east1-b
echo "目前專案：${PROJECT_ID}"
```

- `"你的專案ID"`：換成你的專案 ID（Console 上方的專案選單看得到），雙引號保留

**你應該會看到**：`Updated property [core/project].`，接著印出你的專案 ID。出現 `WARNING: You do not appear to have access to project` 代表專案 ID 打錯了。

## 步驟 1：取得小幫手的網址，先確認現在打得開

講義沒有對應的 Console 動作：先記下「拿掉之前」的狀態。

```bash
export VM_IP=$(gcloud compute instances describe quiz-helper-vm --zone=${ZONE} \
  --format="value(networkInterfaces[0].accessConfigs[0].natIP)")
curl -s --max-time 5 http://${VM_IP}/healthz; echo
```

- `--max-time 5`：最多等 5 秒，連不上就放棄

**你應該會看到**：`{"status":"ok","version":"v1"}`

## 步驟 2：看 VM 現在有哪些標記

對應講義：VM「編輯」頁面的「網路標記」。

```bash
gcloud compute instances describe quiz-helper-vm --zone=${ZONE} --format="value(tags.items)"
```

**你應該會看到**：`http-server`

## 步驟 3：拿掉 http-server 標記

對應講義：取消勾選「允許 HTTP 流量」，按「儲存」。

```bash
gcloud compute instances remove-tags quiz-helper-vm --zone=${ZONE} --tags=http-server
```

- `remove-tags`：從 VM 拿掉網路標記。VM 不用重開，立即生效

## 步驟 4：再連一次

對應講義：重新整理小幫手的網址，一直轉圈。

```bash
curl -s --max-time 5 http://${VM_IP}/healthz; echo "結束代碼：$?"
```

- `$?`：上一個指令的結束代碼。`28` 代表逾時

**你應該會看到**：沒有任何回應，最後印出 `結束代碼：28`。封包被防火牆默默丟掉，所以不是「拒絕」，而是「等不到」。

## 步驟 5：看看 default-allow-http 這條規則

對應講義：「VPC 網路 → 防火牆」找到 default-allow-http。

```bash
gcloud compute firewall-rules describe default-allow-http \
  --format="yaml(name,network,sourceRanges,allowed,targetTags)"
```

**你應該會看到**：`targetTags` 是 `http-server`。規則還在，但專案裡已經沒有任何 VM 帶著這個標記，所以它什麼也沒放行。
