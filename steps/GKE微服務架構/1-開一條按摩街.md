# 1. 開一條按摩街

> 對應講義：微服務架構：Google Kubernetes Engine → Lab 實作 →「開一條按摩街」
>
> 先完成 DevSecOps 章的 [1-切到下一版的程式碼](../DevSecOps軟體供應鏈/1-切到下一版的程式碼.md) 與 [2-用 Cloud Build 把 v1.1 送進成品倉](../DevSecOps軟體供應鏈/2-用CloudBuild把v1.1送進成品倉.md)：程式碼要停在 `lab-2`，存放區裡要有 `quiz-helper:v1.1`。

## 步驟 1：設定這一章會用到的變數

講義沒有對應的 Console 動作。

```bash
cd ~/cloudshell_open/cxcxc-gcp-ace-quiz-helper
git describe --tags
gcloud config set project <你的專案 ID>
export PROJECT_ID=$(gcloud config get-value project)
export PROJECT_NUMBER=$(gcloud projects describe ${PROJECT_ID} --format="value(projectNumber)")
export REGION=asia-east1
export NODE_SA=${PROJECT_NUMBER}-compute@developer.gserviceaccount.com
export IMAGE_V1=${REGION}-docker.pkg.dev/${PROJECT_ID}/quiz-helper/quiz-helper:v1
export IMAGE_V11=${REGION}-docker.pkg.dev/${PROJECT_ID}/quiz-helper/quiz-helper:v1.1
echo "專案：${PROJECT_ID}（編號 ${PROJECT_NUMBER}）｜節點服務帳戶：${NODE_SA}"
```

- `git describe --tags`：確認程式碼在 `lab-2`，`deploy/gke/` 的部署檔只有這個版本才有
- `PROJECT_NUMBER`：專案編號，下一個小 Lab 組 Kubernetes 服務帳戶的主體名稱會用到
- `NODE_SA`：Compute Engine 預設服務帳戶，Autopilot 叢集的節點預設用它

**你應該會看到**：`git describe --tags` 印出 `lab-2`，接著印出專案 ID、專案編號與節點服務帳戶。

> Cloud Shell 斷線重連後，重新執行這一步即可。

## 步驟 2：啟用 Kubernetes Engine API

對應講義：在程式庫搜尋 Kubernetes Engine API，按「啟用」。

```bash
gcloud services enable container.googleapis.com
```

**你應該會看到**：`Operation "operations/..." finished successfully.`，或沒有輸出（代表之前已啟用）。

## 步驟 3：讓節點能從成品倉進貨、寫紀錄

對應講義：在 quiz-helper 存放區授予節點服務帳戶「Artifact Registry 讀取者」，再到 IAM 授予「Kubernetes Engine 預設節點服務帳戶」。

```bash
gcloud artifacts repositories add-iam-policy-binding quiz-helper \
  --location=${REGION} \
  --member="serviceAccount:${NODE_SA}" \
  --role="roles/artifactregistry.reader" \
  --format=none

gcloud projects add-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${NODE_SA}" \
  --role="roles/container.defaultNodeServiceAccount" \
  --condition=None \
  --format=none
```

- 第一段：授權只給在 `quiz-helper` 存放區上，跟 IAM 進階章給小幫手服務帳戶的做法一樣，節點只能到這一間成品倉進貨
- `roles/container.defaultNodeServiceAccount`：節點執行時需要的基本權限，包含把紀錄與指標寫進 Cloud Logging、Cloud Monitoring
- `--condition=None`：不加條件；IAM 進階章加過條件的專案，不寫這個參數會跳出詢問

**你應該會看到**：兩個指令都沒有錯誤訊息。

```bash
gcloud artifacts repositories get-iam-policy quiz-helper --location=${REGION} \
  --format="table(bindings.role, bindings.members)"
```

**你應該會看到**：`roles/artifactregistry.reader` 底下多了 `serviceAccount:<專案編號>-compute@developer.gserviceaccount.com`，跟 IAM 進階章的 `quiz-helper` 服務帳戶並列。

> 出現 `Service account ... does not exist`：Compute Engine 預設服務帳戶要啟用 Compute Engine API 才會建立，Compute Engine 章已經啟用過；如果是新專案，執行 `gcloud services enable compute.googleapis.com`，等一兩分鐘再試。

## 步驟 4：建立 Autopilot 叢集

對應講義：Kubernetes Engine →「叢集」→「建立」→ 選 Autopilot，名稱 quiz-helper-cluster、區域 asia-east1。

```bash
gcloud container clusters create-auto quiz-helper-cluster \
  --region=${REGION}
```

- `create-auto`：建立 Autopilot 叢集，節點由 Google 管理，依 Pod 要求的資源計費
- `--region`：Autopilot 一定是地區叢集，控制層與節點分散在地區內的多個可用區（回顧講義第 5 節）

**你應該會看到**：建立需要 **5～10 分鐘**。完成後出現一個表格，`NAME` 是 `quiz-helper-cluster`，`STATUS` 是 `RUNNING`。

> 等待的時間，可以在 Cloud Shell 編輯器打開 `deploy/gke/` 底下的三個 YAML 檔，看看每個檔案的註解。

## 步驟 5：連上叢集

對應講義：叢集清單點「連線」，複製指令到 Cloud Shell 執行。

```bash
gcloud container clusters get-credentials quiz-helper-cluster --region=${REGION}
kubectl get namespaces
kubectl get nodes
```

- `get-credentials`：把連線資訊寫進 Cloud Shell 的 kubeconfig，之後的 `kubectl` 都會連到這個叢集
- `kubectl get namespaces`：確認連得上
- `kubectl get nodes`：列出節點

**你應該會看到**：`get-credentials` 印出 `kubeconfig entry generated for quiz-helper-cluster.`；`get namespaces` 列出 `default`、`kube-system` 等；`get nodes` 可能是 `No resources found`。Autopilot 在還沒有 Pod 時不一定有節點，下一個小 Lab 部署後才會出現。
