# 2. 先發識別證，再讓小幫手開店

> 對應講義：微服務架構：Google Kubernetes Engine → Lab 實作 →「先發識別證，再讓小幫手開店」
>
> 先完成 [1-開一條按摩街](1-開一條按摩街.md)。

## 步驟 1：建立 Kubernetes 服務帳戶

對應講義：在 Cloud Shell 套用 serviceaccount.yaml（只有指令）。

```bash
kubectl apply -f deploy/gke/serviceaccount.yaml
kubectl get serviceaccount quiz-helper
```

- `kubectl apply -f`：照 YAML 檔的內容建立（或更新）資源
- 這個 Kubernetes 服務帳戶就是 Pod 的「員工識別證」，Deployment 裡用 `serviceAccountName: quiz-helper` 指定

**你應該會看到**：`serviceaccount/quiz-helper created`；`get` 列出一筆 `quiz-helper`。

## 步驟 2：組出它在 IAM 裡的主體名稱

對應講義：照指令版組出主體名稱並複製。

```bash
export KSA_PRINCIPAL="principal://iam.googleapis.com/projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/${PROJECT_ID}.svc.id.goog/subject/ns/default/sa/quiz-helper"
echo ${KSA_PRINCIPAL}
```

- `workloadIdentityPools/${PROJECT_ID}.svc.id.goog`：這個專案的 GKE 身分集區，Autopilot 叢集預設就啟用了
- `ns/default/sa/quiz-helper`：`default` 命名空間裡的 Kubernetes 服務帳戶 `quiz-helper`

**你應該會看到**：一整串 `principal://iam.googleapis.com/projects/<專案編號>/...sa/quiz-helper`。

## 步驟 3：直接授予兩個角色

對應講義：IAM →「授予存取權」，新增主體貼上整串主體名稱，角色選「Cloud Datastore 使用者」與自訂的「小幫手值區」。

```bash
for ROLE in roles/datastore.user projects/${PROJECT_ID}/roles/quizHelperBucket; do
  gcloud projects add-iam-policy-binding ${PROJECT_ID} \
    --member="${KSA_PRINCIPAL}" \
    --role="${ROLE}" \
    --condition=None \
    --format=none
done
```

- `for ROLE in ...`：同一個指令跑兩次，各授予一個角色
- `roles/datastore.user`：讀寫 Firestore 題庫
- `projects/${PROJECT_ID}/roles/quizHelperBucket`：IAM 進階章建立的自訂角色，查詢與建立值區、讀取 CSV

**你應該會看到**：沒有錯誤訊息。確認一下：

```bash
gcloud projects get-iam-policy ${PROJECT_ID} \
  --flatten="bindings[].members" \
  --filter="bindings.members:sa/quiz-helper" \
  --format="value(bindings.role)"
```

**你應該會看到**：兩行，`roles/datastore.user` 與 `projects/<專案 ID>/roles/quizHelperBucket`。

> VM 上的小幫手服務帳戶還有「記錄寫入者」與「Artifact Registry 讀取者」；在 GKE 上這兩件事由節點負責（上一個小 Lab 的步驟 3），Pod 不需要。

## 步驟 4：部署小幫手 v1

對應講義：在 Cloud Shell 套用 deployment.yaml 與 service.yaml（只有指令），到「工作負載」看 Pod。

```bash
sed "s|\${IMAGE}|${IMAGE_V1}|g" deploy/gke/deployment.yaml | kubectl apply -f -
kubectl apply -f deploy/gke/service.yaml
kubectl get pods
```

- `sed "s|\${IMAGE}|${IMAGE_V1}|g"`：把 YAML 裡的 `${IMAGE}` 換成 v1 映像檔的完整名稱，再交給 `kubectl apply`
- `-f -`：從前一個指令的輸出讀取 YAML
- `service.yaml`：`type: LoadBalancer`，GKE 會自動建立一個對外的負載平衡器，外部 80 埠轉到 Pod 的 8080 埠

**你應該會看到**：`deployment.apps/quiz-helper created`、`service/quiz-helper created`。Autopilot 第一次部署要先準備節點，Pod 會先 `Pending` 一兩分鐘；重複執行 `kubectl get pods`，直到兩個 Pod 都是 `Running`、`READY` 為 `1/1`。

> 一直 `Pending` 或出現 `ImagePullBackOff`：執行 `kubectl describe pod <Pod 名稱>` 看最下面的 Events。拉映像檔失敗通常是上一個小 Lab 步驟 3 的角色還沒生效，等一兩分鐘再看。

## 步驟 5：拿到外部 IP，用手機答題

對應講義：「Gateway、Service 與 Ingress」頁面看到 quiz-helper 的端點，用手機打開。

```bash
kubectl get service quiz-helper --watch
```

- `--watch`：持續顯示變化，`EXTERNAL-IP` 從 `<pending>` 變成 IP 後按 Ctrl+C 停止

```bash
export LB_IP=$(kubectl get service quiz-helper -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
echo "小幫手網址：http://${LB_IP}"
curl -s http://${LB_IP}/healthz
kubectl get nodes
```

- `-o jsonpath=...`：從 Service 的狀態取出負載平衡器的 IP

**你應該會看到**：`curl` 印出 `{"status":"ok","version":"v1"}`；`kubectl get nodes` 這次列出節點了。用手機打開網址，題庫就是 Compute Engine 章匯入 Firestore 的那一份，可以直接答題。

> 若答題時出現錯誤：剛授予的角色可能要一兩分鐘才生效，等一下後執行 `kubectl rollout restart deployment/quiz-helper` 讓 Pod 重新啟動再試。
