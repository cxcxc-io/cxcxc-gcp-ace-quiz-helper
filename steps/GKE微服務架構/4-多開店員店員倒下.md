# 4. 多開店員、店員倒下

> 對應講義：微服務架構：Google Kubernetes Engine → Lab 實作 →「多開店員、店員倒下」
>
> 先完成 [3-換上新制服滾動更新到v1.1](3-換上新制服滾動更新到v1.1.md)，第二個分頁的迴圈繼續開著。

## 步驟 1：一個指令多開兩個店員

對應講義：在「工作負載」→ quiz-helper 按「動作」→「調整資源配置」，副本數改成 4。

```bash
kubectl scale deployment quiz-helper --replicas=4
kubectl get pods
```

- `--replicas=4`：Pod 從 2 個變成 4 個

**你應該會看到**：

- `deployment.apps/quiz-helper scaled`；多出兩個新 Pod，從 `Pending`、`ContainerCreating` 變成 `Running`（Autopilot 可能要先準備節點，需要一兩分鐘，重複執行 `kubectl get pods` 觀察）
- 新 Pod 變成 `Running` 後，第二個分頁的 `instance` 在 **4 個**名稱之間交替

## 步驟 2：店員倒下，自動補人

對應講義：在「代管 Pod」清單點其中一個 Pod →「刪除」。

```bash
export VICTIM=$(kubectl get pods -l app=quiz-helper -o jsonpath='{.items[0].metadata.name}')
echo "要刪除的 Pod：${VICTIM}"
kubectl delete pod ${VICTIM}
kubectl get pods
```

- `-l app=quiz-helper`：只找標籤是 `app=quiz-helper` 的 Pod
- `{.items[0].metadata.name}`：取第一個 Pod 的名稱
- `kubectl delete pod`：刪掉它，模擬這個 Pod 當機

**你應該會看到**：

- 被刪的 Pod 顯示 `Terminating` 後消失，同時多了一個沒看過的新 Pod；Deployment 一直維持 4 個
- 第二個分頁裡，被刪的 Pod 名稱不再出現，幾十秒後出現新 Pod 的名稱；**整個過程沒有「連線失敗」**

## 步驟 3：縮回 2 個

對應講義：「調整資源配置」把副本數改回 2。

```bash
kubectl scale deployment quiz-helper --replicas=2
```

**你應該會看到**：多出來的 Pod 變成 `Terminating` 後消失，第二個分頁回到 2 個名稱交替。到第二個分頁按 Ctrl+C 停止迴圈。

## 步驟 4：從紀錄找出答錯的題目與 Pod

對應講義：記錄檔探索工具貼上四行查詢條件。

```bash
gcloud logging read \
  'resource.type="k8s_container" AND jsonPayload.event="answer" AND jsonPayload.correct=false' \
  --freshness=1h \
  --limit=5 \
  --format="table(timestamp, jsonPayload.nickname, jsonPayload.question_id, jsonPayload.app_version, resource.labels.pod_name)"
```

- `resource.type="k8s_container"`：紀錄來自 GKE 的容器；Cloud Logging 章在 VM 上查的是 `gce_instance`
- `jsonPayload.correct=false`：只看答錯的
- `resource.labels.pod_name`：是哪一個 Pod 處理的

**你應該會看到**：最近 5 筆答錯的紀錄，`APP_VERSION` 有 `v1` 也有 `v1.1`，`POD_NAME` 是不同的 Pod。

試試看：

- 加上 `AND jsonPayload.app_version="v1.1"`，只看更新後的紀錄
- 加上 `AND jsonPayload.nickname="你的暱稱"`，只看自己的紀錄
